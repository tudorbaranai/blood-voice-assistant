# 04 · Connect the brain and write the prompt

## Goal
Home Assistant uses Ollama as its "brain", with our own instructions (the
**prompt**) that turn a general chatbot into a short-spoken, honest home
assistant. You can test it by typing before any microphone is involved.

## Why a custom prompt
Out of the box, small models ramble, use emojis and lists (unreadable for a
voice), invent facts, can't tell what weekday a date is, and claim to have
turned on lights they can't touch. Each prompt version below fixed something
we actually saw. All versions are in [`prompts/`](../../prompts/).

## Steps

### 1. Add the Ollama integration
**Settings → Devices & services → + Add Integration → Ollama** → URL:
```
http://10.0.2.2:11434
```
`10.0.2.2` is VirtualBox NAT's built-in address for **the Windows host itself**,
so the traffic never leaves the laptop. No `OLLAMA_HOST` change and no firewall
rule were needed. (VirtualBox's NAT option *LocalhostReachable* is on by default.)

### 2. Create the conversation agent
Settings → Devices & services → **Ollama → + Add conversation agent** (or ⚙️ on an existing one):

| Setting | Value | Why |
|---|---|---|
| Model | **`qwen3:4b-instruct`** | chapter 02 |
| Instructions | paste [`prompts/prompt_v6.txt`](../../prompts/prompt_v6.txt) (replace the name with yours) | see below |
| Control Home Assistant | **off** for now (→ *Assist* once devices exist, chapter 08) | no false "done!" claims |
| Think before responding | **off** | thinking costs many seconds |
| Keep alive | **`-1`** (stay in graphics memory forever) | no 5 s reload on the first question |
| Context window size | **`4096`** ⚠️ | Home Assistant otherwise sends **8192**, overriding Ollama's own setting, so more of the model spills onto the slow CPU |
| Name | e.g. **Blood** | |

### 3. Use it in a voice assistant
**Settings → Voice assistants → Assist** (rename it, e.g. "Blood") →
Conversation agent = your Ollama agent → **Prefer handling commands locally: ON**
(simple commands like "turn on the light" are then handled instantly by Home
Assistant's own matcher, without the AI).

### 4. Test by typing
Overview → the **Assist** chat bubble (top right) → ask things. For timings and
what happened at each stage: Settings → Voice assistants → ⋮ → **Debug**.

## The prompt, version by version (what each fixed)

| Version | Change | Because we saw… |
|---|---|---|
| v1 *(not kept)* | first draft with device examples | it **lied** ("The ceiling light is on.") by copying an example, refused recipes and chit-chat ("I can't check, I'm offline"), got weekdays wrong, ended with "let me know if you need anything else" |
| [v2](../../prompts/prompt_v2.txt) | **a live 4-week calendar** generated by Home Assistant's template engine; "answer from your own knowledge, only *live* info is off-limits"; one hard device rule: *"I can't control devices yet."* | wrong weekdays, over-refusal, lying about devices |
| [v3](../../prompts/prompt_v3.txt) | "These examples only show the style. Never repeat them word for word." | answers copied verbatim from the examples |
| [v4](../../prompts/prompt_v4.txt) | renamed to Blood ("you may hear Blood or Blud") | new name |
| [v5](../../prompts/prompt_v5.txt) | **the clock line moved from the top to the very end** | each answer took 4–7 s (see the box below) |
| [v6](../../prompts/prompt_v6.txt) ✅ | English-only rule (no Korean/Chinese/… letters), give opinions, say song lyrics, "never invent people or facts", honest when a date is outside the calendar, **two extra examples** | non-English letters (the voice can't read them), "I'm not sure" for opinions, refusing lyrics, emojis, guessing far-away dates |
| [v7](../../prompts/prompt_v7_devices.txt) ⬜ | real device rules: act only when clearly asked, ask when unsure, never claim success that didn't happen | for when devices are connected (chapter 08) |

The calendar trick (in v2+). Small models can't work out weekdays, so Home
Assistant writes the next 4 weeks into the prompt:
```jinja
{%- for i in range(0, 29) %}
{{ (now() + timedelta(days=i)).strftime("%A %d %B %Y") }}{% if i == 0 %} (today){% elif i == 1 %} (tomorrow){% endif %}
{%- endfor %}
```

> ### 💡 The biggest speed win: put anything that changes at the END of the prompt
> Ollama remembers ("caches") the start of the prompt between questions, but
> only up to the first character that differs. Our clock line (with minutes)
> was at the **top**, so every minute the whole ~1,100-word prompt had to be
> re-read from scratch: 4–7 s per answer on our laptop (Ollama's log showed only
> 76 tokens reused). Moving it to the bottom (v5) keeps the long fixed part
> cached. The calendar changes once a day, so it can stay higher up.

## How good is it? (our bench, `qwen3:4b-instruct`)
[`tests/compare-brains.ps1`](../../tests/compare-brains.ps1) with
[`tests/questions-limits.txt`](../../tests/questions-limits.txt):

| Prompt | Score on our 10 trick questions | Time per answer |
|---|---|---|
| v5 | ≈ 4/10 | 0.8–3 s |
| **v6** | **≈ 7.5/10** | 0.8–2.3 s |

What still fails with v6, and why:
- The bat-and-ball puzzle and counting the R's in "strawberry" are limits of a
  4-billion-parameter model.
- It still sometimes adds Korean letters next to a pronunciation. That gets fixed
  **in code** (chapter 09 strips non-English characters before speaking).

**Lessons:** for small models, **examples beat rules** (a rule alone didn't stop
it guessing Christmas's weekday; one example did). Keep rules short and
unambiguous. Good device **names** matter more than prompt wording.

## What went wrong for us
| Problem | Cause | Fix |
|---|---|---|
| "Failed to connect" adding Ollama | never pinned down (probably a typo, or right after a reboot) | retried `http://10.0.2.2:11434`, worked |
| Model 36% on the CPU | Home Assistant's agent used context **8192** | Context window size **4096** → 27% |
| 4–7 s per answer | clock at the top broke the prompt cache | v5: clock at the end |
| "Prefer handling commands locally" was off | likely reset when the assistant was renamed or recreated | check it after any change to the assistant |
| Temperature experiments | 0.2 vs the default (0.6–0.7) made no real difference | left at default |
